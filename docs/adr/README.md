# 架构决策记录（ADR）

这里记的是**已经生效、且回不去或改起来很贵**的决定：为什么这样、当时的取舍是什么、
代价在哪、什么时候该重新考虑。

规矩（`tests/test_adr.py` 会机械检查）：

- 文件名 `NNNN-kebab-case.md`，编号四位、连号；
- 每篇必须有这几节：`## 背景` / `## 决定` / `## 理由` / `## 替代方案` / `## 后果` / `## 参考`，
  以及一行 `- **状态**：…`；
- **本索引与目录里的文件一一对应**（加一篇就要在这里登记一行）。

ADR 与 `docs/*.md` 的分工：`docs/*.md` 写**现状**（怎么用、边界是什么），
ADR 写**为什么是现在这样**（以及被否决的方案）。两者冲突时以代码与 `docs/*.md` 为准 ——
ADR 是历史与理由，不是操作手册。
